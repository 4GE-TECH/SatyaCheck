## Remaining Work (M1–M7)

### **M1: CallStateReceiver**
**Status:** Not started
**Effort:** 2–3 hours
**What:** Listen for phone call state (RINGING → OFFHOOK → IDLE)
**Files:**
- `android/app/src/main/kotlin/com/satyacheck/CallStateReceiver.kt` — BroadcastReceiver for android.intent.action.PHONE_STATE
- `android/app/src/main/AndroidManifest.xml` — Add `android.permission.READ_PHONE_STATE` and receiver registration
- `lib/call_state.dart` — Dart listener for receiver broadcasts

**Key points:**
- Detects when incoming call arrives (RINGING)
- Broadcasts to Flutter when call answered (OFFHOOK)
- Tracks call end (IDLE)
- No storage, just event listeners

---

### **M2: OverlayManager**
**Status:** Not started
**Effort:** 3–4 hours
**What:** System overlay window showing "Checking..." during call
**Files:**
- `android/app/src/main/kotlin/com/satyacheck/OverlayManager.kt` — WindowManager overlay
- `android/app/src/main/kotlin/com/satyacheck/OverlayLayout.kt` — Compose UI for overlay

**Key points:**

- No clicks, just display

---

### **M3: AudioCapture + RingBuffer**
**Status:** Not started
**Effort:** 4–5 hours
**What:** Capture call audio in background, buffer 3s rolling chunks
**Files:**
- `android/app/src/main/kotlin/com/satyacheck/AudioCapture.kt` — AudioRecord setup
- `android/app/src/main/kotlin/com/satyacheck/RingBuffer.kt` — Circular 3s buffer with 1s overlap
- `android/app/src/main/kotlin/com/satyacheck/SpeakerController.kt` — Force speakerphone
- `lib/audio_service.dart` — Dart interface

**Key constraints:**
- Explicitly disable AcousticEchoCanceler, NoiseSuppressor, AutomaticGainControl
- 16kHz mono (no stereo, no effects)
- Android 12+ API for speakerphone forcing
- Fallback for older APIs
- Captures far-end audio only (caller's voice)

### **M5: ApiClient**
**Status:** Not started
**Effort:** 2–3 hours
**What:** POST audio chunks to backend `/api/screen` endpoint
**Files:**
- `lib/api_client.dart` — Retrofit / Dio HTTP client
- `lib/models/screen_request.dart` — Request: `{session_id, audio_chunk_b64, chunk_index}`
- `lib/models/screen_response.dart` — Response: `{verdict, score, band, reason_codes}`

**Key points:**
- Reads from M3 RingBuffer
- POST every 1s chunk (with 1s overlap context)
- Session ID persists across call
- Streaming: don't wait for all chunks, score improves as call continues
- LAN backend: `http://192.168.x.x:8000/api/screen` (configurable)

## Architecture Reminder

From CLAUDE.md hard rules:

1. **Folder ownership:** Never edit `audio_ml/`, `nlp_rag/`, `server/`, or `contracts.py`
2. **All code in `satyacheck_mobile/`** — no cross-folder edits
3. **No runtime network calls** beyond `/api/screen` endpoint (backend address in `config.dart`)
4. **MethodChannel only communication** between Dart and Kotlin
5. **Async everywhere** — use `asyncio.to_thread` on Kotlin side for heavy work

## Troubleshooting

### "adb: command not found"
Add to PATH:
```powershell
$env:PATH += ";C:\Users\<YourName>\AppData\Local\Android\sdk\platform-tools"
```

### "Unable to locate device"
```bash
adb devices
# If empty:
# 1. Enable USB Debugging on phone
# 2. Run: adb devices (tap "Allow" on phone)
# 3. Retry
```

### "Flutter command not found"
Verify Flutter in PATH:
```bash
which flutter
# Should return: C:\flutter\bin\flutter
```

### Backend connection fails (M5+)
Check backend is running:
```bash
curl http://192.168.x.x:8000/api/ping
```
